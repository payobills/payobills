<RichText>
## Objective

Support three billing types — **monthly** (default), **yearly**, and **prepaid** — so users can track bills with different recurrence patterns. "Done" means: a user can create a bill with any of the three types, see the type in list and detail views, and the type is immutable after creation.

## Scope

**In scope:** Add `billingPeriod` to the `CreateBillDTO` on the backend, add a billing-type pill picker to the add-bill form, show a read-only badge in the detail view, and hide date fields when "prepaid" is selected.

**Not in scope:** Filtering/sorting by billing type, recurring payment automation, notifications, data migration of legacy records (handled by read-time default).
</RichText>

<RichText>
## Approach

The `BillingPeriod` field already exists in NocoDB and the `Bill` model. The work is purely wiring it through the API contract and surfacing it in the UI. Three changes across two apps:

1. **Backend (`apps/bills`)** — Add `BillingPeriod` to `CreateBillDTO` so the `addBill` mutation accepts it. AutoMapper already resolves it by convention. No schema migration.

2. **Frontend — Add Bill form (`apps/ui`)** — Insert a `BillingTypePicker` (three inline pill buttons) between the name and billing-date fields. Default to "monthly". When "prepaid" is selected, hide `billingDate` and `payByDate` inputs. Wire the value into the `addBill` mutation.

3. **Frontend — Bill Detail view (`apps/ui`)** — Show a `BillingTypeBadge` (read-only pill) below the bill title. Fallback: if `billingPeriod` is null/empty, display "monthly".
</RichText>

<RichText>
> **Decision — Immutability enforcement:** Billing type is set at creation and never changed. Enforced by: (1) no update mutation exists, (2) the detail view renders a read-only badge with no edit control. No explicit server-side guard needed since NocoDB has no update-billing-period endpoint.
</RichText>

### Step 2 — Frontend: BillingTypePicker component

Create a new Svelte component `apps/ui/src/src/lib/billing-type-picker.svelte` — three inline pill/toggle buttons. Accepts a `value` binding and dispatches `change`. When "prepaid" is selected, the parent form hides date inputs.
</RichText>

<AnnotatedCode data={{
  filename: "apps/ui/src/src/lib/billing-type-picker.svelte (new)",
  language: "svelte",
  code: `<script lang="ts">
  export let value: string = "monthly";
  const options = ["monthly", "yearly", "prepaid"];
</script>

<div class="picker">
  {#each options as option}
    <button
      class:active={value === option}
      on:click={() => (value = option)}
      type="button"
    >{option}</button>
  {/each}
</div>

<style>
  .picker {
    display: flex;
    border: 1px solid var(--color-base-300);
    border-radius: 0.5rem;
    overflow: hidden;
  }
  button {
    flex: 1;
    padding: 0.5rem 0;
    border: none;
    background: transparent;
    font-size: 0.8rem;

### Step 3 — Wire BillingTypePicker into the Add Bill form

In `apps/ui/src/src/routes/bills/add/+page.svelte`:
- Import `BillingTypePicker`
- Add a `billingPeriod` variable (default `"monthly"`)
- Insert the picker between the name and billing-date fields
- Conditionally hide `billingDate` and `payByDate` when `billingPeriod === "prepaid"`
- Pass `billingPeriod` to the `addBill` mutation variables
</RichText>

<AnnotatedCode data={{
  filename: "apps/ui/src/src/routes/bills/add/+page.svelte",
  language: "svelte",
  code: `<!-- Add to script block -->
import BillingTypePicker from "$lib/billing-type-picker.svelte";
let billingPeriod: string = "monthly";

<!-- Add to mutation -->
mutation ($name: String!, $payByDate: Int, $billingDate: Int, $billingPeriod: String) {
  addBill(billDto: {
    name: $name
    payByDate: $payByDate
    billingDate: $billingDate
    latePayByDate: 0
    billingPeriod: $billingPeriod
  }) { ... }
}

<!-- Add to form, between name input and billing date -->
<div>billing type</div>
<BillingTypePicker bind:value={billingPeriod} />

{#if billingPeriod !== "prepaid"}
  <div>billing date</div>
  <input type="number" placeholder="1" bind:value={billingDate} />
  <div>pay by date</div>
  <input type="number" placeholder="12" bind:value={payByDate} />
{/if}`,
  annotations: [

}} />

## Verification

1. **Create monthly bill** — Open add-bill form, leave "monthly" selected, fill name/dates, save. Verify bill appears with "monthly" badge.
2. **Create yearly bill** — Select "yearly", fill all fields, save. Badge shows "yearly".
3. **Create prepaid bill** — Select "prepaid", verify date fields disappear, save without dates. Badge shows "prepaid".
4. **Immutability** — Open any bill detail. Billing type is a non-interactive badge. No edit control.
5. **Legacy fallback** — View a bill in NocoDB with empty `BillingPeriod`. UI shows "monthly".
</RichText>
